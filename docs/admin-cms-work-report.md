# 后台管理系统工作说明

日期：2026-08-18

## 修改目的

当前网站原本是纯静态 HTML 网站，所有内容都写在各个页面文件里。客户如果要更新医生、专科、科普文章、首页轮播、联系方式或图片资源，需要直接修改 HTML，维护成本高，也容易改乱页面结构。

本次建设后台管理系统的目标是：

- 让客户通过后台界面更新网站内容。
- 将医生、专科、科普文章、媒体资源等内容从页面代码中逐步抽离成可管理数据。
- 保持前台现有视觉设计不变，后台只负责管理文字、图片路径、排序、显示状态和内容数据。
- 为后续接入真实发布、图片上传、权限登录、预约管理等功能打基础。

## 已完成进度

- 已创建后台页面：`admin/index.html`
- 已创建后台样式：`admin/admin.css`
- 已创建后台交互脚本：`admin/admin.js`
- 已在现有 26 个静态页面页脚加入“后台管理”按钮，统一跳转到 `admin/index.html`
- 已新增页脚后台入口样式：`css/style.css`

2. 新增后台内容数据文件

- 已创建内容数据文件：`data/site-content.json`
- 当前数据包含：
  - 医生：3 条
  - 专科：2 条
  - 科普文章：2 条

3. 新增本地内容服务

- 已创建无第三方依赖的 Node 服务：`server.js`
- 服务能力：
  - 访问静态网站页面
  - 访问后台页面
  - 读取内容 API：`GET /api/content`
  - 保存内容 API：`POST /api/content`
  - 保存时自动备份旧数据到 `data/backups/`
- 已在 `.gitignore` 忽略运行时备份目录：`data/backups/`

4. 修复后台数据读取逻辑

- 后台优先读取 `../api/content`
- 如果 API 不可用，会继续读取 `../data/site-content.json`
- 如果本地浏览器里已有更完整的草稿数据，才使用本地草稿
- 避免后台在静态访问时显示医生、专科、文章、媒体全部为 0

5. 同步现有媒体资源

- 已扫描并同步 `images/` 目录下现有图片和图标资源

## 当前使用方式

本地运行：

```bash
node server.js
```

访问网站：

```text
http://localhost:8080/
```

访问后台：

```text
http://localhost:8080/admin/
```

如果直接打开静态 HTML 文件，后台仍可读取 `data/site-content.json` 展示内容；但真正写入项目文件需要通过 `server.js` 提供的保存接口。

## 当前限制

目前后台还是第一阶段 CMS 基础版，已经能管理数据，但前台页面尚未完全改造为动态读取后台数据。

暂未完成的部分：

- 前台首页、医生页、专科页、科普页还没有全部改为从 `data/site-content.json` 渲染。
- 后台没有登录和权限控制。
- 媒体库目前管理的是现有图片路径，还没有实现图片上传。
- 预约表单还没有接入后台预约记录。
- 发布流程还没有做草稿、预览、审核、发布状态。
- 数据保存依赖 `server.js`，如果只用静态文件访问，保存会进入浏览器本地草稿。
