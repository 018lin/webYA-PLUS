# 后台管理系统工作说明

日期：2026-08-18（更新：2026-08-19）

## 修改目的

当前网站原本是纯静态 HTML 网站，所有内容都写在各个页面文件里。客户如果要更新医生、专科、科普文章、首页轮播、联系方式或图片资源，需要直接修改 HTML，维护成本高，也容易改乱页面结构。

本次建设后台管理系统的目标是：

- 让客户通过后台界面更新网站内容。
- 将医生、专科、科普文章、媒体资源等内容从页面代码中逐步抽离成可管理数据。
- 保持前台现有视觉设计不变，后台只负责管理文字、图片路径、排序、显示状态和内容数据。
- 为后续接入真实发布、图片上传、权限登录、预约管理等功能打基础。

- 如需改为 Public Blob，可在 Vercel 环境变量中设置 `CMS_BLOB_ACCESS=public`

## 当前使用方式

本地运行：

```bash
node server.js
```

访问网站：

```text
http://localhost:8080/
```

访问后台：

```text
http://localhost:8080/admin/
```

如果直接打开静态 HTML 文件，后台仍可读取 `data/site-content.json` 展示内容；但真正写入项目文件需要通过 `server.js` 提供的保存接口。

Vercel 部署：

```text
https://正式域名/
https://正式域名/admin/
https://正式域名/api/content
```

Vercel 上必须满足：

- 项目已部署最新 `main` 分支代码。
- Vercel 项目已连接 Blob Storage。
- Vercel 项目环境变量中存在 `BLOB_READ_WRITE_TOKEN`。
- 当前代码默认按 Private Blob 读写 CMS 数据。
- 如果 Blob 设置为 Public，可额外设置环境变量：`CMS_BLOB_ACCESS=public`。
- 每次调整 Blob 或环境变量后，需要重新部署 Production。

后台状态判断：

- `已连接保存接口`：后台已连上 `/api/content`，可以保存到服务器端。
- `内容已保存`：内容已写入服务端数据源，本地和跨设备刷新后可见。
- `本地草稿已保存，未写入服务器`：没有连上 API，只保存在当前浏览器，前台和其他设备不会同步。
- `Cannot save content data. Connect a Vercel Blob store...`：Vercel API 已部署，但 Blob Storage 或环境变量未正确接入。

## 当前限制

目前后台还是第一阶段 CMS 基础版，已经能管理数据；首页、医生团队页、特色专科页、科普列表页和科普详情页已接入动态读取，但部分详情页和业务流程仍是静态内容。

暂未完成的部分：

- 医生个人详情页、专科详情页仍主要是静态 HTML，尚未完全由后台字段驱动。
- 首页联系方式等全站公共内容尚未全部接入动态渲染。
- 后台没有登录和权限控制。
- 预约表单还没有接入后台预约记录。
- 发布流程还没有做草稿、预览、审核、发布状态。
- 本地开发保存依赖 `server.js`；Vercel 线上保存依赖 Vercel Blob。
- 如果只用静态文件访问，或 Vercel 没有接入 Blob，保存会进入浏览器本地草稿或直接返回保存错误。
